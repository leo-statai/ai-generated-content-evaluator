# Plan for Python Evaluation Script

This document outlines the development plan for a Python script designed to automatically evaluate the quality of an AI-generated technical report using the Gemini API.

## 1. Objective

The primary goal of the script is to programmatically assess a given technical report against a set of predefined quality metrics. It will use the Gemini API to perform the evaluation and output a structured report with quantitative scores and qualitative justifications for each metric.

## 2. Inputs & Configuration

*   **Technical Report File:** The script will require the path to the Markdown file of the report generated by NotebookLM.
*   **Source Transcript File:** To verify factual accuracy, the script will need the path to the original seminar transcript which serves as the ground truth.
*   **API Key:** A Google AI API key must be provided, preferably through a secure method like an environment variable (`.env` file).

## 3. Core Script Components

### 3.1. Setup and Dependencies

*   **Dependencies:** The script will require the `google-generativeai` library. A `requirements.txt` file should be created.
*   **Configuration:** A module or function to load the API key from an environment variable.

### 3.2. File Handling

*   A utility function to read the content of the input files (technical report and transcript) into strings.

### 3.3. Evaluation Module

This will be the core of the script. It will iterate through a series of predefined evaluation functions, one for each quality metric.

**Defined Quality Metrics & Evaluation Strategy:**

For each metric, a specific prompt will be engineered to instruct the Gemini model to act as a specialized evaluator. The model should return a JSON object containing a `score` (integer 1-10) and a `justification` (string).

1.  **Clarity and Coherence:**
    *   **Persona:** Academic Reviewer.
    *   **Task:** Assess the readability, flow, and logical structure of the report.
    *   **Prompt Snippet:** `"...Evaluate the clarity and coherence of the following report. Is the language clear and unambiguous? Does the document flow logically from one section to the next? Return a JSON object with 'score' (1-10) and 'justification'."`

2.  **Factual Accuracy:**
    *   **Persona:** Fact-Checker.
    *   **Task:** Compare the report against the source transcript to identify any factual errors, omissions, or misinterpretations.
    *   **Prompt Snippet:** `"...You will be given a source transcript and a technical report. Your task is to verify the factual accuracy of the report against the transcript. Identify any discrepancies. Return a JSON object with 'score' (1-10) and 'justification' listing any errors found."`

3.  **Depth of Analysis:**
    *   **Persona:** University Professor.
    *   **Task:** Evaluate whether the report provides insightful analysis beyond a surface-level summary.
    *   **Prompt Snippet:** `"...Assess the depth of analysis in this report. Does it offer critical insights, implications, or connections to broader themes as a graduate-level document should? Return a JSON object with 'score' (1-10) and 'justification'."`

4.  **Structural Adherence:**
    *   **Persona:** Academic Journal Editor.
    *   **Task:** Check if the report conforms to the required academic structure (e.g., includes Title, Abstract, a logical sequence of sections).
    *   **Prompt Snippet:** `"...Evaluate the report's adherence to a formal academic structure. Is it well-formatted and does it contain all the necessary components of a technical report? Return a JSON object with 'score' (1-10) and 'justification'."`

### 3.4. API Interaction

*   A robust function to handle API calls to the Gemini model.
*   It will take the evaluation prompt and text as input.
*   It should include error handling for API failures and be able to parse the JSON output from the model.

## 4. Main Execution Flow

The main function of the script will orchestrate the entire process:

1.  Initialize the Gemini API client.
2.  Load the content from the technical report and transcript files.
3.  Create a dictionary to store the results.
4.  Loop through each defined metric:
    a.  Call the corresponding evaluation function.
    b.  Store the returned score and justification.
5.  Calculate an overall average score from the individual metric scores.
6.  Generate the final output.

## 5. Output

The script will produce a final evaluation summary in two formats:

1.  **Console Output:** A clean, human-readable table printed to the console, showing each metric, its score, and justification.
2.  **File Output:** A structured Markdown file (`evaluation_results.md`) containing the detailed results for documentation and reporting purposes.
